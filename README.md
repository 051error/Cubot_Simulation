# cubot_ws

ROS 2 + MuJoCo simulation and control stack for **cubot**, a six-legged (hexapod)
robot with a PhantomX-style 3-DOF leg layout (yaw coxa + pitch femur + pitch
tibia). Locomotion is generated by a central-pattern-generator (CPG) and solved
through inverse kinematics (IK), with an optional reinforcement-learning (RL)
policy trained on top of the CPG layer.

## Overview

The stack is organized around a three-stage pipeline:

```
CPG (Hopf oscillators)  →  foot target  →  IK  →  joint angles  →  MuJoCo
```

- A **tripod-gait CPG** produces a phase (`x`) and quadrature (`y`) signal per leg.
- A **foot trajectory** maps those signals to a body-frame foot target that sweeps
  a straight line opposite to the commanded velocity.
- An **analytic IK** (C++) or a **KD-tree IK** (Python, for RL) converts each foot
  target into three absolute joint angles.
- The **MuJoCo simulator** integrates the physics and publishes the robot state
  back to the controller at 200 Hz.

## Features

- **Three locomotion modes**, switched with the gamepad shoulder buttons:
  - **NORMAL** — joystick-driven CPG walking (forward / backward / lateral).
  - **TURN** — fixed-parameter CPG for in-place rotation.
  - **RL** — a trained PPO policy drives all 18 leg joints via the CPG layer.
- **Body-frame straight-line foot sweep** (no coxa arc), which removes the
  sideways slip that an arc trajectory leaked on the corner legs.
- **Two IK backends** sharing the same leg geometry: a closed-form C++ solver for
  real-time control, and a fast KD-tree lookup for RL rollouts.
- Automated **slip / straight-line** and **turn-balance** test scripts.

## Architecture

`mj_sim` is split into a pure-C++ **gait** module and a ROS-aware **controller**:

```
mj_sim/
├── include/mj_sim/
│   ├── gait.hpp          # GaitGenerator, TripodGait, FootTrajectory, TurnGait, LegGeometry
│   ├── ik_solver.hpp     # LegIK (analytic 3-DOF inverse kinematics)
│   └── robot_ctrl.hpp    # XboxController + RobotController
├── src/
│   ├── gait.cpp
│   ├── ik_solver.cpp
│   ├── robot_ctrl.cpp    # mode state machine + ROS IO (main)
│   └── xbox_controller.cpp
├── msg/
│   ├── LowState.msg      # /mujoco/low_state (joints, IMU, feet, contacts)
│   └── UpCmd.msg         # /upper_ctrl (high-level velocity command)
├── models/
│   ├── scene.xml         # world + floor
│   └── cubot.xml         # robot MJCF (generated by convert_urdf.py)
└── scripts/
    ├── mujoco_simulator.py            # MuJoCo physics + /mujoco/low_state publisher
    ├── convert_urdf.py                # URDF → MJCF converter
    ├── leg_ik.py                      # KD-tree IK (used by RL)
    ├── hexapod_cpg.py                 # Hopf-oscillator CPG (used by RL)
    ├── train_rl.py                    # PPO training (arXiv:2310.07744 style)
    ├── rl_inference.py                # RL policy node
    ├── test_straight_line.py          # slip + straight-line test
    ├── test_turn_balance.py           # turn balance test
    └── analysis_workspace_velocity.py # foot workspace / CPG velocity analysis
```

## Dependencies

- **Ubuntu** (tested on 24.04) with **ROS 2 Jazzy**.
- **MuJoCo 3.3.2** and `mujoco-viewer` (pip).
- ROS packages: `rclcpp`, `sensor_msgs`, `std_msgs`, `ament_index_cpp`, `joy`.
- Python (for simulation / RL): `numpy`, `scipy`, `gymnasium`, `stable-baselines3`,
  `torch`.

## Build

```bash
cd cubot_ws
source /opt/ros/jazzy/setup.bash
colcon build --symlink-install
source install/setup.bash
```

## Run

Start the simulator (opens the MuJoCo viewer) and the controller in two terminals:

```bash
# Terminal 1 — physics + state publisher
ros2 run mj_sim mujoco_simulator.py

# Terminal 2 — controller (also forks joy_node for the gamepad)
ros2 run mj_sim robot_ctrl
```

A GUI is required for the viewer; set `DISPLAY` if running over SSH.

## Control modes

Gamepad mapping (Xbox layout):

| Input | Meaning |
| --- | --- |
| Left stick Y (`axes[1]`) | forward / backward (NORMAL) |
| Left stick X (`axes[0]`) | lateral left / right (NORMAL) |
| Right stick X (`axes[3]`) | turn direction & rate (TURN) |
| `RB` (buttons[5]) | TURN mode (hold) |
| `LB` + `RB` | RL mode (hold) |
| `Y` (buttons[3]) | open the lid |

- **NORMAL** — no shoulder buttons. Left stick drives CPG walking.
- **TURN** — hold `RB`, push right stick left/right for in-place rotation.
- **RL** — hold `LB` + `RB`, with `rl_inference.py` running:

  ```bash
  ros2 run mj_sim rl_inference.py
  ```

## ROS 2 topics

| Topic | Type | Direction | Purpose |
| --- | --- | --- | --- |
| `/mujoco/low_cmd` | `Float64MultiArray` | controller → sim | 19 joint commands (18 legs + lid) |
| `/mujoco/low_state` | `mj_sim/LowState` | sim → controller | joint pos/vel/torque, IMU, feet, contacts |
| `/mujoco/last_ctrl` | `Float64MultiArray` | sim → debug | last applied control |
| `/joy` | `sensor_msgs/Joy` | gamepad → controller | raw joystick |
| `/upper_ctrl` | `mj_sim/UpCmd` | controller → RL | high-level velocity command |
| `/rl_action` | `Float64MultiArray` | RL → controller | policy-driven 18 joint targets |

## Testing

Two automated scripts measure the behavior the controller cares about. They
publish `/joy` themselves, so stop `joy_node` (or the physical gamepad) first to
avoid two publishers fighting over the topic. Run them with the simulator up and
the workspace sourced (so the `mj_sim.msg` definitions resolve):

```bash
# Slip + straight-line test (NORMAL mode, forward then backward)
python3 src/mj_sim/scripts/test_straight_line.py --duration 15

# Turn balance test (TURN mode, fast then slow)
python3 src/mj_sim/scripts/test_turn_balance.py --duration 30
```

## RL training

The RL pipeline follows the CPG+RL architecture of
[arXiv:2310.07744](https://arxiv.org/abs/2310.07744) (terrain-adaptive CPGs with
RL for hexapod locomotion): the policy outputs 8 CPG foot-trajectory parameters,
the Hopf oscillators turn them into foot positions, and the KD-tree IK solves the
joint angles.

```bash
# Train (checkpoints land in src/mj_sim/rl_checkpoints/)
python3 src/mj_sim/scripts/train_rl.py --total_steps 5000000

# Run the trained policy (publishes /rl_action)
ros2 run mj_sim rl_inference.py
```

## Coordinate conventions

- **Body frame**: X = forward, Y = left, Z = up.
- **Leg order**: `rf, rm, rr, lf, lm, lr` (right-front … left-rear).
- **Joints**: angle `0` = straight leg. The crouched reference pose is
  `coxa = 0`, `thigh = -0.7593`, `tibia = -0.7108` (all six legs identical).
- **Leg frame (c1_rest)**: X = vertical (up), Y = forward/outward, Z = lateral.
